# Task 2 Short Report Paragraph

The app can be modelled as a simple local authentication system. `MainActivity` acts as the launcher screen and allows the user to enter a username and password for registration, which are then stored in the local file `credentials.txt`. The user can then navigate to `Login`, where the app reads the stored credentials and compares them with the supplied input. If the credentials match, the app generates a session token and stores it in `SharedPreferences` (`SessionPrefs`), then opens the `Profile` screen. The main security-sensitive assets in this model are the username, password, stored credentials, and session token. The key trust boundary exists between user input, application logic, and local storage, since the current code review shows no clear backend interaction.
