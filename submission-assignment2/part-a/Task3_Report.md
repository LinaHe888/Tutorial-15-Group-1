The application exhibits an insecure transport configuration that enables man-in-the-middle (MITM) attacks. Static analysis identifies multiple insecure transport paths, including cleartext communication and disabled TLS validation. Specifically, cleartext traffic is permitted via android:usesCleartextTraffic="true" in AndroidManifest.xml, and is actively used in MainActivity.java through webView.loadUrl("http://www.example.com"). In addition, certificate validation is bypassed in the WebView by invoking sslErrorHandler.proceed() in onReceivedSslError(...), and hostname verification is disabled via a HostnameVerifier that always returns true. As a result, an on-path attacker can read and modify network traffic: HTTP requests can be directly intercepted due to lack of encryption, while HTTPS connections can be intercepted by presenting a forged certificate that the app accepts. This is unsafe because it breaks the core guarantees of secure communication—confidentiality, integrity, and authenticity—allowing the attacker to effectively impersonate the server. In the worst case, this enables credential and session token theft, sensitive data disclosure, malicious content injection into the WebView, and manipulation of application behavior.
